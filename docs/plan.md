## Task 5: Period engine

**Files:**
- `src/lib/engine/periods.ts` — create

**Functions to implement:**
- `calculatePeriodBoundary(resetPeriod: string, resetAnchor: string, now: Date, statementDay?: number, anniversaryDate?: Date): { periodStart: Date; periodEnd: Date | null }` — pure function, no DB
- `ensureCurrentPeriod(benefitId: string): Promise<BenefitPeriod>` — checks DB, closes expired, creates new if needed

**Boundary rules:**

| resetPeriod | resetAnchor | periodStart | periodEnd |
|---|---|---|---|
| monthly | calendar | 1st of current month 00:00 | Last day of month 23:59:59 |
| quarterly | calendar | 1st of current quarter 00:00 | Last day of quarter 23:59:59 |
| annual | calendar | Jan 1 current year 00:00 | Dec 31 23:59:59 |
| monthly | statement | Last occurrence of statementDay | Next occurrence − 1 day |
| annual | anniversary | Last anniversary date | Next anniversary − 1 day |
| once | any | Benefit's `createdAt` | null |

**`ensureCurrentPeriod` logic:**
1. Query latest open BenefitPeriod for benefit
2. If exists AND `periodEnd > now` (or null) → return it, no DB write
3. If exists AND expired → UPDATE `status = 'closed'` → INSERT new open period → return new
4. If none → INSERT first period → return it

**Acceptance criteria:**
- [x] `calculatePeriodBoundary` is a pure function — no DB, no side effects
- [x] Returns correct boundaries for all 6 combinations in table above
- [x] `ensureCurrentPeriod`: no DB write when valid open period exists
- [x] `ensureCurrentPeriod`: closes expired period before creating new (never skips close step)
- [x] Closed periods (`status: 'closed'`) NEVER updated — only new records inserted (per CONSTRAINT-08)
- [x] [EH-01] DB errors throw with `{ fn: "ensureCurrentPeriod", benefitId }` context
- [x] [CQ-01] Each function < 50 lines

**Tests required:**
- `calculatePeriodBoundary monthly/calendar` → `returns Apr 1–Apr 30 when now = Apr 15`
- `calculatePeriodBoundary quarterly/calendar` → `returns Apr 1–Jun 30 when now = May 1`
- `calculatePeriodBoundary annual/calendar` → `returns Jan 1–Dec 31 of current year`
- `calculatePeriodBoundary once` → `returns periodEnd = null`
- `ensureCurrentPeriod` → `returns existing open period without DB write when still valid`
- `ensureCurrentPeriod` → `closes expired period and creates new when periodEnd < today`
- `ensureCurrentPeriod` → `creates first period when none exist`

## Task 6: Usage engine + Expiring engine

**Files:**
- `src/lib/engine/usage.ts` — create
- `src/lib/engine/expiring.ts` — create

**Functions to implement:**
- `usage.ts`: `updateBenefitUsage(benefitId: string, newAmount: number): Promise<BenefitPeriod>`
- `expiring.ts`: `isExpiringSoon(benefit: BenefitWithPeriod, daysThreshold?: number): boolean`
- `expiring.ts`: `aggregateOverview(cards: UserCardWithBenefits[]): OverviewData`

**`updateBenefitUsage` rules:**
1. Call `ensureCurrentPeriod(benefitId)`
2. Clamp `newAmount` to `[0, benefit.value]` (if benefit.value not null)
3. UPDATE `BenefitPeriod.usedAmount` where `id = period.id AND status = 'open'`
4. Return updated period

**`isExpiringSoon` rules (all must be true):**
- `tracked = true`
- `resetPeriod ≠ 'once'`
- `periodEnd` within `daysThreshold` days of today (default 7)
- Unused value > 0: credit/perk: `usedAmount < value`; subscription: `usedAmount === 0`; access with cap: `usedAmount < value`; access uncapped: false

**`aggregateOverview` rules:**
- Filter: `type === 'credit' || type === 'perk'`
- Group by category
- Per group: `totalAvailable = sum(benefit.value)`, `totalUsed = sum(currentPeriod.usedAmount)`
- Exclude categories where `totalAvailable === 0`

**Acceptance criteria:**
- [x] `updateBenefitUsage` is the ONLY function that writes `usedAmount` to DB (per CONSTRAINT-07)
- [x] Clamps to `[0, benefit.value]` before write
- [x] Throws `{ fn: "updateBenefitUsage", benefitId, newAmount }` if no open period after `ensureCurrentPeriod`
- [x] `isExpiringSoon` returns false for non-trackable benefits
- [x] `isExpiringSoon` returns false for `resetPeriod: 'once'`
- [x] `aggregateOverview` excludes `subscription` and `access` types
- [x] `aggregateOverview` excludes categories where totalAvailable = 0
- [x] [EH-01] DB errors in usage.ts throw with benefitId + newAmount context
- [x] [CQ-01] Each function < 50 lines

**Tests required:**
- `updateBenefitUsage` → `clamps to benefit.value when newAmount exceeds cap`
- `updateBenefitUsage` → `throws when no open period found`
- `isExpiringSoon` → `true when credit has unused value and resets in 3 days`
- `isExpiringSoon` → `false when fully used`
- `isExpiringSoon` → `false for once-type benefits`
- `aggregateOverview` → `sums credits across cards by category, excludes subscription and access`
